# Устройство игр

«Дрейф» и «Апекс» остаются самостоятельными Vite-проектами. У каждой игры свои зависимости, ресурсы и сборка. Общая стилистика не требует общего игрового движка.

## Кеплер: Дрейф

`src/game.ts` связывает состояние экспедиции, управление кораблём, сцену, звук и смену фаз. Он задаёт порядок обновления: движение и столкновения корабля → выстрелы → сбор руды → эффекты → переход сектора.

| Модуль | Ответственность |
| --- | --- |
| `state.ts` | Состояние забега, урон, экономика, стоимость и покупка улучшений |
| `asteroids.ts` | Тип астероида для симуляции, выстрелов и интерфейса |
| `projectiles.ts` | Создание лазеров, время жизни, первое попадание на всём отрезке движения |
| `salvage.ts` | Кристаллы, магнит, ограниченный пул, награда и сбор при смене сектора |
| `flight-effects.ts` | Частицы и осколки, пределы количества и очистка при рестарте |
| `boost.ts`, `maneuvers.ts`, `camera.ts`, `collision.ts` | Форсаж, бочки, стабильная камера и тело столкновений корабля |
| `models.ts`, `environment.ts`, `storm.ts` | Геометрия, окружение и молнии |
| `ui/shell.ts`, `ui/dom.ts`, `ui/hud.ts` | Разметка, иконки, приборы, прицел и радар |
| `main.ts`, `loading.ts` | Запуск, загрузка, диалоги, мастерская и действия интерфейса |

Системы выстрелов, руды и эффектов владеют своими временными объектами. `reset()` убирает их из сцены; частицы также сразу получают пустой диапазон отрисовки. Геометрия и материалы астероидов используются повторно и сохраняются при удалении осколков.

`Salvage` сообщает о подобранной руде через callback, а `Game` записывает её в баланс забега. Заполненный пул из 150 кристаллов объединяет награды в существующем кристалле. `collectAll()` перед мастерской собирает оставшуюся награду один раз; рестарт удаляет остатки без начисления в новую экспедицию.

Эффекты и руда получают функцию случайных чисел от `Game`. Она обращается к текущему генератору забега, поэтому его сброс не оставляет подсистемы со старым seed. Порядок вызовов генератора сохранён.

## Кеплер: Апекс

`src/game.ts` управляет загрузкой, вводом, фазами гонки и циклом кадров. `stepRace()` обновляет правила маленькими шагами до 1/120 секунды. Затем `RaceView` читает состояние и обновляет видимые объекты.

| Модуль | Ответственность |
| --- | --- |
| `rules.ts`, `physics.ts` | Правила, соперники, время кругов, заряд, сцепление и столкновения |
| `race-view.ts` | Анимация кузова, колёс и выхлопа, камера, портретное кадрирование |
| `track.ts`, `scenery.ts`, `car.ts`, `environment.ts` | Трасса, безопасное размещение объектов, болиды и орбита |
| `motion-blur.ts`, `tire-trails.ts`, `audio.ts` | Размытие, следы шин и звук |
| `ui/shell.ts`, `ui/dom.ts`, `ui/hud.ts` | Разметка, иконки, приборы, позиции и мини-карта |
| `main.ts` | Запуск, диалоги, кнопки управления и локальные рекорды |

Вход `RaceView` содержит только читаемые данные гонки. Сброс вида очищает крен и тангаж; сброс камеры при изменении размера заново устанавливает кадрирование. Физика, секундомер и порядок финиша остаются в `rules.ts`. HUD получает текущий лучший круг через функцию, чтобы сохранённый рекорд отображался и после следующего заезда.

## Проверки при изменениях

В каждой папке игры выполняются `npm test` и `npm run build`. Всего 65 автоматических тестов: 39 для «Дрейфа» и 26 для «Апекса». Новые проверки охватывают ближайшее попадание, одно уничтожение на залп, истечение снарядов, сохранение награды, магнит, очистку эффектов, независимость вида от правил и портретное кадрирование реального болида.

Браузерные fixtures «Дрейфа» доступны через dev-сервер: `/tests/flight-probe.html` проверяет 39 сценариев реальной игры, `/tests/collision-probe.html` — урон и столкновения, `/tests/render-probe.html` — итоговые WebGL-кадры трёх секторов. Fixtures публикуют результаты в DOM; production-вход не предоставляет отладочного доступа к игре.
